# Implementation status

Last verified phase: Notifications and Reminders, 2026-08-08.

Implemented and build-verified: typed environment configuration; NestJS API boundary; PostgreSQL repository/transaction foundation; opaque sessions; activation and password reset tokens; TOTP enrollment/verification/recovery; re-authentication; session list/revoke; global Origin/CSRF/session/MFA guard; React login, MFA, activation, reset and session pages; vi-VN/en-US catalogs; OpenAPI validation; outbox dispatcher; Student, Submission and Manual Transfer foundational use cases.

Automated gates verified: Prettier, typed ESLint, TypeScript, Redocly OpenAPI, Vitest and production builds. PostgreSQL migrations are verified against local PostgreSQL 16 databases; object-storage and antivirus adapter integration is verified against Docker MinIO and ClamAV.

Resource authorization phase implemented: authenticated actor context now includes effective student linkage; Student list/detail/create/update are deny-by-default and school/self scoped; academic submission and manual-transfer idempotency are actor-bound; out-of-scope resources are concealed with 404. Migration 004 adds effective-dated one-to-one user/student linkage.

Organization/Programs/Periods/Calendars phase implemented: authorized managers can list, create and optimistically update schools, programs, academic periods and calendar overrides; schools/programs can be activated or deactivated from the localized web UI. Migration 005 adds lifecycle flags, period opening windows and holiday/working-day overrides. Calendar rules move deadlines across weekends/holidays while honoring explicit working days. Validation failures now return structured 422 field errors.

Student/Guardian/Duplicate/Transfer History phase implemented: student create/update append immutable profile versions; creation initializes school history; duplicate candidates are normalized-name/date-of-birth checked within caller scope and require an explicit reason to override; guardian contacts are AES-GCM encrypted/HMAC indexed and masked on reads; school transfer is a dedicated optimistic, scoped transaction that appends history and profile versions. The localized Student UI supports create/list, guardian management, school history and transfer.

Academic submission/review phase implemented: scoped users can create unique drafts, save typed JSON with optimistic locking, submit actor-bound idempotent immutable snapshots, and view their scoped list/review queue. School and program review decisions enforce state, reason, workflow level and reviewer separation; one-level approvals finish immediately while two-level approvals create a final task. Review outcomes publish through the transactional outbox. The localized UI supports draft JSON, submission and review decisions. Migration 007 adds draft metadata, queue indexes, review completion timestamps and an append-only database trigger for submitted versions.

Documents phase implemented: authorized owners initiate a private S3-compatible quarantine upload, clients provide SHA-256/size/MIME metadata, completion verifies object metadata and magic bytes, and a transactional outbox dispatches the ClamAV scan. The worker streams bounded objects through ClamAV, deletes infected objects, or promotes clean objects to a private clean prefix; downloads require clean/promoted state and use five-minute signed URLs. The localized UI computes SHA-256 in-browser and performs direct signed uploads. Migration 008 adds storage lifecycle, uploader, completion/scan timestamps and scan queue indexes.

Banking phase implemented: students can create or replace their own effective-dated account using optimistic locking; account holder and number are AES-GCM encrypted with a separate normalized HMAC, and every ordinary response remains masked. Program managers can validate or reject pending accounts. Full reveal requires a stated purpose and a session re-authenticated in the preceding five minutes, and appends a redacted audit event. The localized web UI performs re-authentication immediately before reveal and does not persist plaintext bank fields. Migration 009 adds review evidence, timestamps, consistency checks and operational indexes.

Manual Transfers phase implemented: authorized managers record only externally executed transfers after validating student, period and active bank prerequisites. Program managers, effective school managers and linked students receive deny-by-default scoped list/detail views. Linked students append one idempotent received/not-received confirmation; non-receipt opens investigation. Manager corrections never overwrite financial evidence: they mark the original corrected, create a replacement, and append an immutable linkage with reason and approver. Request hashes reject idempotency-key reuse with different payloads, school scope is snapshotted, and all state changes publish through the outbox. Migration 010 adds scope/creator/deadline metadata, evidence uniqueness/indexes and database triggers preventing confirmation/correction updates or deletes.

Education Expenses and Support Programs phase implemented: yearly VND/USD expense tracking enforces academic-year and numeric bounds, grade 9-and-below school management, grade 10-and-above student self-management, optimistic locking and an idempotent draft/submit/return/confirm/correct workflow. Confirmed values cannot be silently edited; correction appends a reasoned version and returns the record to draft. Expense evidence uses the private scanned-document workflow. TAP, DESK and Reading Room occurrences support scoped create/list/update/archive with received date, tracked value, state, notes and append-only version history. The localized UI covers both workflows. Migration 011 adds expense/support records, catalogs, histories, indexes and append-only triggers.

Local infrastructure verification: Docker Desktop 4.84.0 is running with Redis 7, MinIO, Mailpit and healthy ClamAV containers. A direct PostgreSQL 16.14 service is running on port 55432; database `vnsf_test` successfully applied migrations 001-013. Clean and EICAR-infected document flows, notification delivery, reminder scheduling and SMTP delivery passed real PostgreSQL/MinIO/ClamAV/Mailpit integration tests. Expense/support workflows passed a dedicated PostgreSQL integration database. Runtime package exports were corrected so compiled API/migration code loads compiled config rather than TypeScript source.

Extensions and Thank-you Letters phase implemented: scoped students and school managers can request a later effective academic-submission deadline while a partial unique constraint prevents simultaneous open requests. Program managers approve or reject with optimistic locking and mandatory reasons; approval updates the snapshotted effective deadline and publishes an outbox event for reminder cancellation/rescheduling. Thank-you letters are unique by student and period, support editable drafts, immutable submitted versions, CLEAN document evidence, one/two-level review, reviewer separation and final approval locking. Migration 012 adds effective deadlines, extension evidence, thank-you records/version/review tables and append-only triggers. The localized web UI and OpenAPI contract cover both workflows.

Local Compose runtime hardened: Nginx serves the SPA on 8080 with history fallback and `/api` reverse proxy; API/worker use internal service DNS; MinIO initialization creates a non-public private bucket before application startup.

Notifications and Reminders phase implemented: PostgreSQL-backed reconciliation creates deduplicated T-14/T-7/T-2/T+1/T+7 schedules from each submission effective deadline and active student account. Pre-deadline reminders move to the next configured working day while overdue milestones remain calendar-day based. Submission stops/corrections and approved extensions cancel stale scheduled reminders; the next reconciliation creates schedules from the new deadline. Worker outbox jobs create idempotent in-app and email deliveries, snapshot vi-VN/en-US locale, use versioned templates, send through the configured SMTP relay and persist retry/backoff evidence without making Redis authoritative. Password-reset events now produce actual expiring-link email delivery. Authenticated users have a private inbox, unread count and owned read/read-all mutations in the localized UI. Migration 013 adds reminder schedules, templates, delivery lifecycle/retry fields and notification dedupe keys.
